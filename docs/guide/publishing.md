# 检查与发布

交付的是静态组件目录，不是 Git 仓库、源码依赖树或用户数据。当前本地导入不接受 ZIP；不要以打包下载链接替代宿主目录选择。

## 发布前检查

1. 清点最终输出：manifest、入口 HTML、所有本地脚本/样式/资源及可选 PNG 预览；不能含 SDK 三件套、密钥、调试日志、个人文件或远程 JavaScript。
2. 保持稳定 widgetId；正式版本号为三个非负整数。标签使用协议标准英文值，名称和描述不作为身份。新作品用新 UUID。
3. 在真实宿主开发页执行“检查组件包”，再启用验证主要路径、权限拒绝、撤销、隐藏、重载和错误恢复。桌宠补输入/穿透与编辑恢复，游戏补存档冲突，信息流补断网和迟到结果。
4. 核对配置分享字段。秘密、目录授权、凭据、临时句柄和游戏进度不能通过布局或组件包分享。

## 创意工坊

开发页标题右侧的 GitHub 图标可直接打开 [widget-workshop-dev 仓库](https://github.com/wangdiandao/widget-workshop-dev)。

在开发页对应组件详情选择“发布”。宿主校验当前源码并创建清洁上传副本，源码 widgetId 必须匹配所选开发组件；不要求先激活该源码，也不因此替换当前运行版本。

点击“发布”直接打开发布表单，填写标题和说明，核对标签、预览图及可见范围；新发布默认公开。每个作品只保留一项发布记录，位于抽屉的“发布”区域。开始提交后，原发布按钮变灰，后续从下方“更新”进入更新表单。更新沿用只读的条目 ID，只需填写可选的更新说明；创建结果未知时，先找回原条目 ID。更新保留远端标题、作品说明及可见范围。表单不提供操作选择、保存草稿或移除草稿；打开或关闭预览不会创建发布记录。卡片在作品名右侧显示上传版本，成功状态显示“上传成功”。

发布记录和上传操作仍在对应开发组件抽屉；新发布默认公开，检查标题、描述、预览、标签和发布内容后再按宿主流程提交。上传失败不应损坏当前可运行版本。实际服务可用性、账号同意与条款由 Steam 和用户环境决定。

布局从布局抽屉的“发布”直接进入发布表单；已发布布局从下方“更新”进入更新表单。布局弹窗以组件名称与 UUID 列表代替预览图、实际上传文件和原始布局 JSON；可分享配置直接在同一弹窗中勾选并核对值，首次发布默认不选，提交后保留选择；成功后的更新沿用所选字段并刷新配置值。更新时同样可调整分享选择，只会使用准备预览时服务筛选的配置快照。布局发布与更新不生成或上传预览图，更新保留 Steam 条目原有封面。工坊中的布局采用布局库的无图卡片样式；卡片和详情优先使用已下载 layout.json 的校验缓存中的真实分辨率，未下载时才读取线上摘要，两者均不可用时显示“分辨率未知”。组件发布仍使用组件预览图或产品占位图。

布局保存、覆盖与重命名由宿主管理作品版本。上传前核对远端并冻结更高版本；失败或结果未知后重试保持同一内容和版本，失败重试时分享选择只读，成功后再次更新才能修改。导入同身份布局会创建新的本地副本并保留原布局。布局详情展示依赖与兼容性检查，不显示排布示意图。

布局分享只替换目标显示器，缺依赖不能应用，不自动订阅。布局依赖只按组件 UUID 匹配，不保存组件来源，工坊发布无需填写引用或重绑定；不能包含作者源码路径、授权或秘密。规则见[工坊模块](../reference/modules/workshop.md)和[布局协议](../reference/contracts/layout.md)。
